# Job Lens — مراحل ۱ و ۲

افزونهٔ Chrome با Manifest V3 و TypeScript. مرحلهٔ ۱ شامل نصب محلی، پنجرهٔ کوچک و صفحهٔ تنظیمات بود. در مرحلهٔ ۲ آپلود PDF و DOCX، استخراج و بازبینی متن، ذخیرهٔ محلی، ترجیحات شغلی و ثبت رضایت اضافه شده‌اند. نسخهٔ فعلی `0.2.0` است؛ تحلیل LinkedIn و بک‌اند هنوز پیاده‌سازی نشده‌اند.

## مفاهیم و فایل‌ها

- `src/manifest.json`: شناسنامهٔ افزونه؛ نام، نسخه، پنجرهٔ کوچک و صفحهٔ تنظیمات را معرفی می‌کند.
- `src/popup/popup.html`: ساختار پنجره‌ای که با کلیک روی آیکون افزونه باز می‌شود.
- `src/popup/popup.ts`: نمایش نسخه، وضعیت رزومه و رضایت، و بازکردن صفحهٔ تنظیمات با `chrome.runtime.openOptionsPage()`.
- `src/options/options.html`: فرم آپلود، پیش‌نمایش قابل ویرایش، ترجیحات و رضایت.
- `src/options/options.ts`: کنترل فرم، تأیید و ذخیره، جایگزینی، لغو تغییرات و حذف داده‌ها.
- `src/resume/validation.ts`: محدودیت‌ها و اعتبارسنجی پسوند، MIME، امضای فایل و متن استخراج‌شده.
- `src/resume/extractor.ts`: خواندن متن PDF با PDF.js و DOCX با Mammoth، بدون تبدیل متن به HTML.
- `src/resume/extraction.worker.ts`: استخراج خارج از بخش نمایش صفحه برای جلوگیری از مسدودشدن رابط کاربری.
- `src/resume/upload.ts`: ارسال فایل به Worker محلی، توقف پس از ۳۰ ثانیه و لغو خواندن فایل قبلی هنگام انتخاب فایل جدید.
- `src/shared/settings.ts`: مدل داده، اعتبارسنجی و نسخه‌بندی مستقل رزومه و ترجیحات.
- `src/shared/storage.ts`: خواندن و ذخیرهٔ محلی و جلوگیری از ذخیرهٔ تغییرات قدیمی یک تب روی دادهٔ جدید تب دیگر.
- `src/styles.css`: ظاهر مشترک دو صفحه.
- `tsconfig.json`: بررسی نوع‌های TypeScript؛ ساخت JavaScript اکنون با esbuild انجام می‌شود. Chrome فایل TypeScript را مستقیم اجرا نمی‌کند.
- `package.json`: ابزارهای توسعه و دستورهای ساخت.
- `package-lock.json`: ثبت نسخه‌های دقیق وابستگی‌ها برای نصب تکرارپذیر.
- `scripts/build.mjs`: بررسی TypeScript، بسته‌بندی کد و کتابخانه‌ها با esbuild، و کپی صفحه‌ها و دارایی‌های PDF به `dist`.
- `scripts/test.mjs`: تست قوانین فایل، داده، رضایت و ذخیره‌سازی با فایل‌های ساختگی.
- `scripts/test-browser.mjs`: تست آپلود واقعی PDF و DOCX و رفتار صفحه‌ها در مرورگر جدا با Playwright.
- `scripts/test-fixtures.mjs`: تولید فایل‌های آزمایشی؛ هیچ رزومهٔ واقعی در تست‌ها وجود ندارد.
- `.gitignore`: جلوگیری از ثبت خروجی ساخت، وابستگی‌ها و فایل‌های متداول حاوی secrets در Git.
- `dist/`: خروجی قابل نصب؛ این پوشه را به Chrome معرفی کن و فایل‌هایش را مستقیم ویرایش نکن.

در مراحل بعد، Content script داخل صفحهٔ LinkedIn اجرا می‌شود. Service worker مسئول کارهای پس‌زمینهٔ افزونه خواهد بود و دائماً فعال نمی‌ماند. Worker استخراج فایل در مرحلهٔ ۲ یک Web Worker معمولی است و با Service worker افزونه فرق دارد؛ وظیفه‌اش فقط خواندن فایل است و پس از اتمام، لغو یا timeout بسته می‌شود.

`typescript` و `chrome-types` برای بررسی نوع‌ها هستند؛ `esbuild` وابستگی‌های مرورگری را به فایل‌های محلی تبدیل می‌کند. PDF.js و Mammoth همراه خود افزونه نصب می‌شوند. Worker، CMapها و فونت‌های PDF نیز محلی‌اند و هیچ کد اجرایی از CDN دریافت نمی‌شود. از build نوع `legacy` در PDF.js برای سازگاری با Chrome 125 به بالا استفاده می‌کنیم؛ این نام به سازگاری کتابخانه مربوط است، نه Manifest V2.

تنها مجوز فعلی `storage` است؛ هیچ دسترسی به سایت‌ها، تب‌ها یا شبکهٔ بک‌اند درخواست نمی‌شود. سیاست امنیتی افزونه فعلاً اتصال و کد را به منابع خودش محدود می‌کند. خواندن فایل و ذخیره‌سازی بدون اینترنت کار می‌کنند؛ نصب وابستگی‌های توسعه به اینترنت نیاز دارد.

## رفتار مرحلهٔ ۲

مسیر اصلی: **آپلود فایل ← استخراج متن ← بازبینی و اصلاح ← تأیید و ذخیرهٔ محلی**. بدون فایل، کادر خالی برای واردکردن دستی رزومه نمایش داده نمی‌شود.

- PDF متنی و DOCX تا ۵ مگابایت پذیرفته می‌شوند. PDF حداکثر ۳۰ صفحه و متن حداکثر ۱۰۰٬۰۰۰ نویسه است.
- متن بسیار کوتاه، خالی یا فاقد حروف و عدد پذیرفته نمی‌شود. حداقل ۴۰ نویسهٔ غیرسفید لازم است؛ این شرط کامل‌بودن رزومه را تضمین نمی‌کند.
- PDF بدون متن خطای روشن دارد؛ اسکن به OCR نیاز دارد و OCR هنوز پیاده‌سازی نشده است. در PDF ترکیبی با صفحه‌های بدون متن، هشدار بررسی محتوای جاافتاده نمایش داده می‌شود.
- فایل رمزدار، خراب، با MIME ناسازگار یا فایل دیگری که فقط نامش به PDF/DOCX تغییر کرده باشد رد می‌شود. اسناد قدیمی DOC پشتیبانی نمی‌شوند.
- ترتیب متن PDF چندستونه ممکن است متفاوت باشد؛ پیش‌نمایش را با اصل فایل مقایسه کن. قالب‌بندی DOCX حفظ نمی‌شود.
- فایل جدید تا زمان تأیید جای رزومهٔ ذخیره‌شده را نمی‌گیرد. فایل اصلی و نام آن ذخیره نمی‌شوند؛ فقط متن تأییدشده، نسخه و زمان تأیید ذخیره می‌شوند.
- تغییر متن نیاز به تأیید دوباره دارد. ذخیرهٔ متن متفاوت، نسخهٔ رزومه را تغییر می‌دهد و رضایت قبلی را خاموش می‌کند. تغییر ترجیحات نسخهٔ مستقل خودش را دارد؛ این نسخه‌ها در مرحلهٔ کش استفاده خواهند شد.
- اطلاعات شخصی خودکار حذف نمی‌شوند. نام، تماس، آدرس دقیق و اطلاعات غیرضروری را پیش از تأیید از پیش‌نمایش پاک کن. ذخیره‌سازی محلی رمزگذاری ویژه‌ای ندارد و مربوط به همین پروفایل مرورگر است؛ به حساب Chrome همگام نمی‌شود.
- زبان و سطح تسلط، شهرهای قابل‌قبول، دورکاری و نوع استخدام ذخیره می‌شوند. مورد خالی به معنی نامعلوم یا بدون ترجیح است.
- رضایت تحلیل خودکار پیش‌فرض خاموش است و فقط پس از تأیید رزومه می‌توان آن را همراه ترجیحات ذخیره کرد. فعلاً این یک ترجیح ذخیره‌شده است و هیچ تحلیل یا ارسال داده‌ای فعال نیست. پیش از اولین ارسال در مرحلهٔ بک‌اند، مقصد معرفی می‌شود و رضایت مرتبط با ارسال دوباره گرفته خواهد شد.
- **Disable automatic analysis** رضایت ذخیره‌شده را خاموش می‌کند. **Delete saved resume** متن رزومه را حذف و رضایت را خاموش می‌کند و ترجیحات را نگه می‌دارد. **Delete all saved data** همهٔ داده‌های Job Lens را حذف می‌کند.
- اطلاعات محلی فقط در اختیار صفحه‌های مورد اعتماد خود افزونه هستند. تغییر یا حذف داده در تب دیگر، فرم قدیمی را متوقف و پیش‌نمایش آن را پاک می‌کند؛ باید **Reload saved settings** را بزنی.

## ساخت در ویندوز

به Node.js نسخهٔ `22.13.0` یا بالاتر و Chrome به‌روز (حداقل ۱۲۵) نیاز داری. در PowerShell اجرا کن:

```powershell
Set-Location 'D:\Projects\Job Lens'
node --version
npm.cmd ci
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
```

`npm.cmd ci` وابستگی‌ها را مطابق فایل قفل نصب می‌کند. از `npm.cmd` استفاده می‌کنیم چون ممکن است PowerShell اجرای `npm.ps1` را مسدود کند. نیازی به تغییر Execution Policy نیست.

در پایان باید پیام زیر را ببینی:

```text
Build complete. Load the dist folder in chrome://extensions.
```

## نصب در Chrome

1. در نوار آدرس Chrome بنویس `chrome://extensions`.
2. گزینهٔ **Developer mode** را روشن کن.
3. روی **Load unpacked** کلیک کن.
4. پوشهٔ `D:\Projects\Job Lens\dist` را انتخاب کن؛ پوشهٔ اصلی پروژه یا `src` را انتخاب نکن.
5. کارت **Job Lens** باید ظاهر شود و روشن باشد.
6. روی آیکون پازل کنار نوار آدرس کلیک کن و Job Lens را Pin کن.

## ارتقا از مرحلهٔ ۱

بعد از build، در `chrome://extensions` روی Reload کارت Job Lens بزن. اگر Chrome برای مجوز جدید `storage` تأیید خواست، آن را بررسی و تأیید کن. پنجرهٔ کوچک را دوباره باز و تب تنظیمات قدیمی را Refresh کن. نسخه باید `0.2.0` باشد. نیازی به حذف و نصب دوباره نیست.

## تست دستی مرحلهٔ ۲

1. روی آیکون Job Lens کلیک کن. باید `Extension is ready` و `Version 0.2.0` را ببینی. قبل از تأیید رزومه، پیام درخواست آپلود نشان داده می‌شود.
2. روی **Open settings** کلیک کن. باید صفحهٔ `Resume & preferences` باز شود و پیام `Settings loaded` را ببینی.
3. آدرس صفحهٔ تنظیمات باید با `chrome-extension://` شروع شود.
4. پنجرهٔ کوچک را دوباره باز کن و دوباره **Open settings** را بزن؛ Chrome باید صفحهٔ تنظیمات افزونه را باز کند یا به صفحهٔ بازشده برگردد.
5. در `chrome://extensions` خطاهای کارت افزونه را بررسی کن. برای دیدن Console پنجرهٔ کوچک، داخل آن راست‌کلیک کن و **Inspect** را بزن. صفحهٔ تنظیمات را هم با DevTools بررسی کن؛ نباید خطای JavaScript وجود داشته باشد.

سپس این موارد را امتحان کن:

1. یک PDF متنی انتخاب کن. پیام خواندن فایل و بعد پیش‌نمایش متن باید ظاهر شود. دکمهٔ ذخیره تا تیک تأیید غیرفعال است.
2. متن را بررسی و اطلاعات شخصی را پاک کن، تیک بازبینی را بزن و **Confirm & save resume** را انتخاب کن. باید پیام ذخیرهٔ محلی نمایش داده شود.
3. زبان و سطح آن، شهرها (هرکدام در یک خط)، دورکاری و نوع استخدام را وارد کن. اگر خواستی، ترجیح تحلیل خودکار را روشن کن. سپس **Save preferences & consent** را بزن.
4. صفحه را Refresh کن؛ متن و ترجیحات باید باقی مانده باشند. پنجرهٔ کوچک هم وضعیت رزومه و رضایت را نشان می‌دهد.
5. یک DOCX انتخاب کن. تا پیش از تأیید، رزومهٔ قبلی باید محفوظ باشد. متن جدید را کمی تغییر بده و تأیید کن؛ ترجیحات باید بمانند و رضایت تحلیل خودکار خاموش شود.
6. فایل خراب، PDF بدون متن یا اسکن‌شده و فایل بیش از ۵ مگابایت را امتحان کن. خطا باید روشن باشد و فایل نامعتبر نباید رزومهٔ ذخیره‌شده را جایگزین کند. در PDF ترکیبی، هشدار صفحهٔ بدون متن را بررسی کن.
7. **Delete saved resume** را بزن و تأیید کن. متن باید حذف شود، ترجیحات بمانند و رضایت خاموش شود. با **Delete all saved data** و تأیید آن، ترجیحات هم حذف می‌شوند.
8. برای بررسی محلی‌بودن عملیات، اینترنت را قطع کن و آپلود و ذخیره را تکرار کن؛ باید کار کنند. Network ممکن است دریافت منابع `chrome-extension://` خود افزونه را نشان دهد؛ هیچ درخواست HTTP برای فایل یا متن وجود ندارد.
9. دو تب تنظیمات باز کن و در یکی داده‌ها را حذف کن. تب دیگر باید پیش‌نمایش قدیمی را پاک و درخواست Reload کند.

در این مرحله صفحهٔ LinkedIn تغییری نمی‌کند و امتیازی نمایش داده نمی‌شود.

## تست مرورگر خودکار (اختیاری)

تست‌های منطقی با `npm.cmd test` اجرا می‌شوند. برای تست واقعی افزونه در مرورگر جدا، ابتدا Chromium تست را داخل پروژه دریافت کن:

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = 'D:\Projects\Job Lens\.browser-cache'
npx.cmd playwright install chromium
npm.cmd run build
npm.cmd run test:browser
```

این تست‌ها روی پروفایل جدا و فایل‌های ساختگی اجرا می‌شوند و به رزومه یا پروفایل Chrome تو دست نمی‌زنند. فایل‌های آزمایشی در `.test-artifacts/fixtures` و تصویرهای صفحه در `.test-artifacts` ساخته می‌شوند و وارد Git نمی‌شوند. می‌توانی `sample-resume.pdf` و `sample-resume.docx` را برای تست دستی هم استفاده کنی. فایل `no-text.pdf` یک PDF آزمایشی بدون متن است، نه یک اسکن واقعی.

تست مرورگر شامل استخراج دو فرمت، بازبینی، ذخیره و reload، ترجیحات، رضایت، خطاهای فایل، توقف فایل کند، انتخاب فایل جدید، حذف و جلوگیری از ذخیرهٔ پیش‌نویس قدیمی است. همچنین خطاهای JavaScript/CSP و درخواست‌های HTTP را بررسی می‌کند. این تست جای آزمایش رزومهٔ واقعی چندستونه یا PDF با فونت خاص را نمی‌گیرد.

## تغییر کد و ساخت دوباره

فایل‌ها را در `src` تغییر بده، سپس اجرا کن:

```powershell
npm.cmd run build
```

در `chrome://extensions` دکمهٔ Reload کارت Job Lens را بزن؛ بعد پنجرهٔ کوچک را دوباره باز کن و تب تنظیمات را Refresh کن.

## خطاهای معمول

- **Manifest file is missing or unreadable**: ابتدا build را اجرا کن و پوشهٔ `dist` را انتخاب کن؛ فایل `dist/manifest.json` باید وجود داشته باشد.
- **Could not load JavaScript / Could not load popup**: build را دوباره اجرا کن، موفقیت آن را بررسی کن و افزونه را Reload کن.
- **نسخه به‌جای عدد، خط تیره است یا دکمه کار نمی‌کند**: Console پنجرهٔ کوچک را بررسی کن. HTML را مستقیم با `file://` باز نکن؛ باید از آیکون افزونه اجرا شود.
- **npm.ps1 cannot be loaded**: دستورها را با `npm.cmd` اجرا کن.
- **node یا npm.cmd شناخته نمی‌شود**: Node.js را نصب کن و ترمینال را دوباره باز کن.
- **خطای دریافت بسته‌ها**: اتصال اینترنت و دسترسی به npm registry را بررسی کن؛ نصب وابستگی‌ها اینترنت می‌خواهد.
- **تغییرات دیده نمی‌شوند**: فایل‌های `src` را تغییر بده، build را اجرا کن، افزونه را Reload کن و صفحه‌های بازشده را تازه کن.
- **Load unpacked وجود ندارد**: Developer mode را روشن کن. مرورگر مدیریت‌شدهٔ سازمانی ممکن است نصب افزونهٔ محلی را محدود کند.
- **Could not read saved settings**: مطمئن شو افزونه Reload و مجوز `storage` فعال شده است؛ بعد **Reload saved settings** را بزن. اگر دادهٔ ذخیره‌شده خراب است، با **Delete all saved data** و تأیید آن تنظیمات را پاک کن.
- **The file reader could not start** یا خطای Worker: دوباره build بگیر و افزونه را Reload کن؛ فایل `dist/vendor/pdf/pdf.worker.min.mjs` باید موجود باشد. کد اصلی و Worker از یک نسخهٔ PDF.js ساخته می‌شوند.
- **There is too little extractable text**: PDF را باز کن و ببین متنش قابل انتخاب است یا فقط تصویر است. برای اسکن، OCR لازم است؛ متن بسیار کوتاه هم پذیرفته نمی‌شود.
- **Password-protected PDFs are not supported**: نسخهٔ بدون رمز فایل خودت را خروجی بگیر و دوباره امتحان کن.
- **Reading this file took too long**: خواندن پس از ۳۰ ثانیه متوقف می‌شود. فایل کوچک‌تر یا خروجی تازه‌ای از رزومه انتخاب کن.
- **Settings changed in another tab**: روی **Reload saved settings** بزن؛ پیش‌نویس قدیمی نباید اطلاعات حذف‌شده را دوباره ذخیره کند.
- **دکمهٔ ذخیرهٔ ترجیحات غیرفعال است**: ابتدا پیش‌نویس رزومه را تأیید و ذخیره کن یا تغییرات آن را با **Discard unsaved changes** کنار بگذار.
- **تست مرورگر می‌گوید executable وجود ندارد**: دستور نصب Chromium بالا را با همان `PLAYWRIGHT_BROWSERS_PATH` اجرا کن.

نسخه‌های دقیق PDF.js، Mammoth و ابزارهای ساخت در `package.json` و `package-lock.json` ثبت شده‌اند. ساختار API مدل و محدودیت‌های رایگان Cloudflare پیش از مرحلهٔ اتصال بک‌اند بررسی خواهند شد؛ هیچ ادعایی دربارهٔ رایگان یا نامحدودبودن سرویس نداریم.

پس از تست، نتیجهٔ آپلود PDF و DOCX، ذخیره پس از Refresh، ترجیحات و حذف رزومه را گزارش کن. مرحلهٔ بعد فقط با گزارش تو یا درخواست «ادامه بده» شروع می‌شود.
